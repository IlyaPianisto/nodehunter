### ТЕКУЩАЯ АРХИТЕКТУРА "NodeHunter"

Проект делится на 5 больших блоков. Данные идут от поиска к конечному юзеру (клиенту).

#### БЛОК 1: Сборщики и Ищейки (Управление TG-аккаунтами и источниками)
*   **Управление сессиями (прямо в Web-панели):**
    *   Раздел, где ты вводишь номер телефона -> получаешь код в ТГ -> вводишь код в панель -> создаётся `.session` файл.
    *   Можно добавить несколько аккаунтов. У каждого есть галочка: «Участвует в парсинге» или «Отдыхает».
    *   Прямо в панели можно посмотреть «Список чатов» конкретного аккаунта и управлять ими (легковесное меню).
*   **Умный поиск новых источников:**
    *   Скрипт мониторит твои любимые «каналы-дропы».
    *   Если он видит репост из незнакомого канала с ключами, или ссылку на новый VPN-канал, он **автоматически предлагает его добавить** в базу (или добавляет сам).
    *   Также можно руками скармливать GitHub-ссылки (raw) или сайты-доноры.

#### БЛОК 2: Мозг (Gemini Router + Xray Конвертер)
Скрипты `main.py` и `sub_fetcher.py` объединяются в мощный конвейер:
*   **Роутер ключей Gemini:** В базе лежат ключи от Google. Конвейер берет сырой текст из ТГ-канала, берет нелимитированный API-ключ и скармливает текст ИИ. Окончился лимит? Незаметно переключается на следующий ключ.
*   **Разбор полётов:**
    *   *Нашли инструкцию по абузу / ТГ-бота?* -> Отправляем в таблицу «Заабузить!» (с приоритетом, датой и ссылкой).
    *   *Нашли прямые ключи (vless://...)?* -> Специальный скрипт конвертирует их в Xray JSON (outbound).
    *   *Нашли ссылку на подписку?* -> `sub_fetcher` маскируется под клиента, качает её, достает оттуда все ноды и каждую тоже конвертирует в Xray JSON.
*   Все найденные ноды падают в базу данных PostgreSQL со статусом `Ожидает проверки`.

#### БЛОК 3: Хардварный Тестер (Телефон + Termux)
Устройство на столе (Huawei) выполняет грязную работу по проверке:
*   Телефон держит связь с сервером. Сервер кидает ему пачку непроверенных JSON-outbound'ов.
*   **Шаг 1 (Wi-Fi):** Скрипт на телефоне запускает ядро Xray, проверяет пинг/доступность. Мёртвые отсеиваются.
*   **Шаг 2 (LTE):** Скрипт через Termux отключает Wi-Fi, переходит на симку. Проверяет оставшиеся ноды на **обход ТСПУ (Белых списков)**.
*   Отправляет отчёт на сервер. Сервер записывает в БД: «Эта нода работает и обходит всё, живёт до такого-то числа».

#### БЛОК 4: База Данных PostgreSQL
Единое хранилище всего:
*   `tg_sessions` (ТГ-аккаунты для парсинга).
*   `sources` (Каналы, сайты, гитхабы).
*   `nodes` (Те самые outbounds в JSON, их статусы и даты смерти).
*   `tasks` (Задачи на абуз).
*   `users` (Люди, которым ты раздаёшь VPN).
*   `settings` (Шаблоны Xray, Gemini API-ключи).

#### БЛОК 5: Web-Панель (Flask + Jinja) и Дистрибуция
Олдскульная, строгая панель по твоим наброскам:
1.  **Главная:** Статистика (CPU, RAM, кол-во серверов/рабочих) + Таблица «Что заабузить сегодня!».
2.  **Пользователи:** Добавление/удаление юзеров (с привязкой Telegram/Телефона).
3.  **Хосты (Ноды):** Список рабочих Xray-JSON нод. Можно выбрать, к какому шаблону они относятся, продлить/посмотреть дату окончания, удалить.
4.  **Источники/Инструкции:** Управление парсингом и ТГ-аккаунтами.
5.  **Настройки:** Смена логина/пароля панели, пути подписки, управление токенами.
6.  **Генератор подписки (API):** Клиент стучится по секретной ссылке -> Сервер берет "Xray Шаблон" -> Вставляет туда рабочие ноды -> Отдаёт клиенту.
